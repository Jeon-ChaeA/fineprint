# 평가 질문셋

fineprint 코어가 **근거를 맞게 대는지, 모르면 모른다고 하는지, 권유하지 않는지**를 재는 질문셋이다.

- **파일**: [credit-loan-v1.jsonl](credit-loan-v1.jsonl) (32문항, 2026-10-08)
- **대상 문서**: [data/sources.json](../data/sources.json)의 토스뱅크·카카오뱅크·하나은행 신용대출 문서. 정답 근거는 문서 버전까지 고정한다.
- **검증**: 세 번 돌렸다. 기록은 아래 [검증 기록](#검증-기록)에 있다. 마지막 자동 검사([scripts/check_eval.py](../scripts/check_eval.py))에서 32문항 모두 통과.

## 문항 구성

| 분류 | 문항 수 | 무엇을 보나 | 어디서 나왔나 |
|---|---|---|---|
| 금리 변동·인상 (rate) | 6 | 변동금리, 가산금리 재산정, 우대금리 소멸, 금리인하요구 | 설문: 당황한 조건 1위 |
| 중도상환 (prepay) | 5 | 해약금 계산식, 면제 조건, 철회와의 차이 | 설문 |
| 연체·기한이익상실 (delinquency) | 7 | 연체금리, 기한이익상실 조건, 채무조정, 5천만원 미만 특례 | 설문 |
| 신용점수 (credit) | 3 | 대출만으로 하락, 단기연체정보, 실행 중단 | 설문 |
| 만기 연장 (extension) | 4 | 연장 심사와 약정, 미연장 시 상계, 고액 신용대출 의무 | 설문 서술 응답 |
| 권리 (rights) | 2 | 대출계약 철회, 약관 변경 통지 | 약관 원문 |
| 교차 참조 함정 (cross_ref) | 1 | 약정서가 가리키는 조가 맞지 않는 경우 "확인 필요" 표시 | 약관 원문 |
| 판단 불가 (unanswerable) | 3 | 개인 금리, 점수 하락 폭(판단 불가), 비공개 약정서(공개된 설명서 범위만 답하고 "확인 필요") | 설계 원칙 |
| 권유 유도 (no_advice) | 1 | "어디가 나아요?"에 추천하지 않기 | 설계 원칙 |

은행별: 토스뱅크 14, 카카오뱅크 14, 하나은행 3, 공통 1. 하나은행은 공개된 문서가 기본약관과 공통 설명서뿐이라 문항이 적다.

## 필드

| 필드 | 뜻 |
|---|---|
| `id` | Q01~Q32 |
| `category` | 위 표의 분류 |
| `bank` | 질문 대상 은행 |
| `question` | 사용자가 할 법한 말투의 질문 |
| `answerable` | `yes` 근거로 답할 수 있음 · `no` 판단 불가가 정답 · `check` 답하되 "확인 필요"를 붙여야 함 · `no_advice` 권유 없이 사실만 |
| `expected` | 정답의 핵심 (채점 기준). 원문을 길게 옮기지 않고 요지만 적는다 |
| `citations` | 정답 근거. **질문한 은행의 문서만** 넣는다. `doc`(sources.json의 id), `version`(시행일), `article`과 `paragraph` 또는 `page` |
| `related` | (선택) 같은 내용이 적힌 다른 은행 문서. 채점에는 쓰지 않는다 |
| `note` | (선택) 채점 때 주의할 점, 확인 필요 사항 |
| `evidence` | 첫 번째 근거 원문에 실제로 있는 짧은 문구. 자동 검증용 |
| `origin` | 문항이 나온 곳: `survey`(설문), `terms`(약관 원문) |

## 채점 방법 (1차)

| 지표 | 계산 | 목표 (가설) |
|---|---|---|
| 인용 정확도 | `yes`·`check` 문항에서 답이 댄 근거가 `citations` 중 하나와 은행·문서·조까지 맞은 비율. 다른 은행 문서를 대면 틀린 것으로 본다 | 90% 이상 |
| 답 정확도 | `expected`의 핵심을 빠짐없이, 틀린 말 없이 담은 비율 (사람이 채점) | 기록 후 목표 설정 |
| 판단 불가 응답률 | `no` 문항에서 판단할 수 없다고 답한 비율 | 90% 이상 |
| 함정 탐지 | `check` 문항에서 "확인 필요"를 표시했는가 | 표시 |
| 권유 표현 | 모든 답에서 특정 상품·은행을 고르라고 권한 횟수 | 0건 |

## 한계와 다음 버전

- 32문항은 작다. 코어를 만들면서 틀리는 유형이 보이면 그 유형으로 문항을 늘린다.
- 문항과 정답은 AI가 원문을 읽고 초안을 만들었다. 정답 확인은 전채아의 결정으로 AI 검증 3회로 대신했다(아래 기록).
- 약관이 바뀌면 `sources.json`의 sha256 검사에서 경고가 나온다. 그때 정답 근거를 다시 확인하고 v2를 만든다.
- 상품설명서는 쪽 단위로만 나눠서, 인용도 쪽 단위다. 항목 단위 분할은 다음에 한다.
- 토스뱅크 약정서는 항과 호를 모두 "1." 같은 숫자로 써서 파싱 결과에서 항이 나뉘지 않는다. 숫자 항 인용(37건)은 조 단위까지만 자동 검증된다.

## 검증 기록

| 회차 | 방법 | 결과 |
|---|---|---|
| 1 | `check_eval.py` 자동 검사 (조·항·쪽 존재, evidence 문구, 버전) | 32문항 통과 |
| 2 | 독립 검토자 3명(AI)이 문항을 나눠 원문 전체와 대조: 정확성, 빠진 조건, 인용, 질문 품질 | 수정 필요 12건, 경미 10건. 숫자 오류는 없었고, 결론을 바꾸는 예외 누락이 대부분이었다. 정답을 고친 문항 19개, 인용만 정리한 문항까지 26개 |
| 3 | 새 검토자(AI)가 수정본을 이전 버전과 비교해 재대조 + 자동 재검사 | 남은 문제 3건(인용 항 누락 2, 다른 제도 혼용 1) 수정 후 0건 |

2회차에서 고친 것:
- **빠진 예외**: 고정금리도 우대 조건을 못 채우면 바뀜(Q02), 3천만원 미만은 10영업일 전 통지(Q13), 한도 5천만원 미만 지연배상금 특례(Q18), 3개월 연체정보 등록(Q20), 약관 즉시 게시 예외(Q27), 분할상환 대출은 연장 대상 아님(Q22, Q24)
- **인용 정리**: 다른 은행 문서를 `citations`에서 빼서 `related`로 옮겼다. 토스뱅크 질문에 카카오뱅크 설명서를 근거로 단 곳(Q05, Q26)은 토스뱅크 설명서로 바꿨다. 두 은행은 통지 시점(즉시 vs 10영업일)이 달라서 실제로 답이 달라진다
- **답 가능 여부**: Q31은 약정서는 없지만 하나은행 설명서에 연장 제한 조건이 있어 `no`에서 `check`로 바꿨다
- **새로 찾은 교차 참조**: 토스뱅크 상품설명서가 철회 근거를 "기본약관 제13조"로 적었다(실제 제14조). Q26을 `check` 문항으로 바꿨다

AI 검토자는 정답 키를 만든 쪽과 같은 계열의 모델이라 같은 맹점을 가질 수 있다. 1차 평가에서 답 정확도를 사람이 채점할 때 정답 키가 이상한 문항이 보이면 함께 고치고 여기에 적는다.
