# fineprint

> 금융 약관의 깨알 같은 조건을, 근거 조항과 함께 읽어 주는 AI 에이전트

**라이브 데모 (베타)**: https://fineprint-i8hy.onrender.com · 토스뱅크·카카오뱅크·하나은행 신용대출 공시 문서 11개 + 하나카드·BC카드 신용카드(베타)

만든 사람: 전채아 · 2026-10-06 ~ (사이클 1 신용대출, 사이클 2 신용카드 완료)

## 한 장 요약

| | |
|---|---|
| **문제** | 신용대출을 받는 사람은 동의 직전 **나에게 불리할 수 있는 조건**을 모른다. 85%가 약관을 거의 읽지 않고, 앱의 요약 화면은 절반 넘게 기억하지 못한다. 나중에 당황하는 건 금리·한도 같은 숫자가 아니라 조건이다. |
| **해결** | ① 불리할 수 있는 조건 6줄 요약 (줄마다 조항 원문) ② 내 상황을 물으면 조항을 찾아 근거와 함께 답하고, 문서로 정할 수 없으면 **판단할 수 없다고 말하는** 답변 |
| **신뢰 설계** | 검색·교차 참조 확인·인용 검증·안전장치는 **코드**가 하고, 모델은 준 근거 안에서 문장만 쓴다. 근거 목록에 없는 인용은 코드가 걸러 내서, 모델을 바꿔도 신뢰 장치는 그대로 남는다 |
| **검증** | 72문항 평가(인용 정확도 100%, 답 정확도 97% · Claude 기준), 처음 보는 질문 85개로 안전장치 확인, 사용성 테스트 3회 |
| **결과물** | 배포된 베타, [PRD](docs/prd.md), [기업용 도입 제안서](docs/proposal-enterprise.md), [회고](docs/retrospective.md), 결정 기록 11건 |

## 문제: 근거 (설문 39명, 앱 4곳 관찰)

- **85%**가 약관을 거의 읽지 않는다. 이유는 "너무 길다"(92%). 한 번의 대출 조회에 133쪽, 217쪽짜리 동의서가 따라온다.
- 대출을 알아본 사람의 **52%**가 앱의 요약 화면을 기억하지 못한다.
- **51%**가 가입 뒤 당황한 조건이 있다. 금리가 오르는 조건, 신용점수 영향, 만기 연장 조건이다.
- AI 설명을 믿으려면 **조항 원문**(59%)과 **모르면 모른다**(38%)가 필요하다고 답했다.

→ [문제 정의](docs/problem-statement.md) · [설문 결과](research/survey-results.md) · [앱 관찰](research/app-observation.md)

## 만든 것

```
질문 → 은행·층별 조항 검색(BM25 + 용어 사전) → 참조 조항 따라가기 → 교차 참조 확인
     → AI 분류기(결과 예측 질문인가, 없는 문서를 묻는가)
     → 초안(LLM) → 점검(LLM) → 인용 검증·안전장치(코드) → 화면
```

- **불리할 수 있는 조건 요약**: 은행별 6줄. 문서끼리 다르게 적힌 줄은 '확인 필요'를 단다. 금융 용어 23개에 점선 풀이.
- **조항 근거 답변**: 답변 / 확인 필요 / 판단할 수 없음 세 상태. 결론 한 줄을 먼저, 끝에 "지금 할 수 있는 일"과 "다음에 할 일"(은행에 무엇을 물을지).
- **안전장치** ([guard.py](fineprint/guard.py)): 결과 예측 질문, 수집하지 않은 문서, 근거 없는 답, 다른 대출 유형 조건 섞임, 본문과 배지 불일치, 요약과 답의 불일치를 코드가 표시한다.
- **배포**: Render 무료 서버 + 무료 Gemini 3.5 flash-lite ([D-010](docs/decision-log.md)). 약관 원문은 공개 레포에 두지 않고 비공개 데이터 레포에서 배포할 때 받는다.

## 어떻게 검증했나

| 무엇 | 결과 | 문서 |
|---|---|---|
| 인용 정확도 (72문항, 5개 질문셋) | **100%**, 지어낸 인용 0, 권유 0 | [results-v1.6](eval/results-v1.6.md) |
| 답 정확도 (Claude, 3회 다수결, 블라인드) | 1차 72% (32문항) → 1.6 **97%** (O 70/72), 버전 6번 개선 | [eval/](eval/README.md) |
| 근거 재현율 (항 단위) | 86% → **97%** | [results-v1.5](eval/results-v1.5.md) |
| 배포 모델 (Gemini flash-lite + 안전장치) | O 39 · △ 32 · **X 1** (틀린 단정은 거의 없고, 빠뜨림이 많음) | [results-gemini](eval/results-gemini.md) |
| 안전장치 (처음 보는 질문 85개) | 판단 불가 **26/26**, 없는 문서 **14/14**, 과한 조심 4% | [results-guard](eval/results-guard.md) |

평가에서 배운 것: **처음 보는 문항으로 재지 않으면 개선을 착각한다.** 점검 단계(1.2)는 기존 문항에서만 좋아 보였고, 정규식 안전장치는 규칙을 만든 문항에서 10/10, 처음 보는 질문에서 4/15였다.

## 사용자 테스트

| 회차 | 방식 | 핵심 결과 | 반영 |
|---|---|---|---|
| 1차 | 지인 5명, 혼자 써 보고 설문 | 근거 원문 신뢰 중앙값 4/5, '판단할 수 없음'에 더 믿음 3/4. 막힌 곳은 용어와 물어보기 동선 | 용어 풀이, 줄마다 물어보기 ([결과](research/usability-results.md)) |
| 2차 | AI 가상 사용자 5명, 실제 서버 답 10개 | 요약 줄 오류 1, 틀린 답 2, 근거 없는 답 1 | 요약 수정, 안전장치 2개, 결론 먼저, 다음에 할 일 ([결과](research/usability-test-2-synthetic.md)) |
| 3차 | AI 가상 사용자 3명 × 원문/fineprint, 이해도 퀴즈 | 3분 뒤 퀴즈 5문항: 원문 3.0 vs **fineprint 5.0** | 배지 불일치 등 5가지, 요약 2줄 ([결과](research/usability-test-3-synthetic.md)) |

2·3차는 실제 사람이 아니라서 성공 기준 판정에는 쓰지 않았다. 대출 경험자 실제 테스트는 [설계](research/usability/test-3-plan.md)와 [설문 페이지](survey/usability3.html)까지 준비돼 있다.

## 배운 것 ([회고](docs/retrospective.md))

- **"모르면 모른다"가 가장 비싼 기능이었다.** 강한 모델은 지시만으로 지켰지만, 무료 모델은 정규식 + AI 분류기 + 코드 안전장치가 필요했다.
- **실패는 대부분 검색에서 시작했다.** 사용자 말과 약관 말의 차이("원금부터 줄어들게" ↔ "채무변제충당순서")는 용어 사전 몇 줄이 프롬프트 수정보다 효과가 컸다.
- **원문도 함정이다.** 같은 은행의 상품설명서와 약정서가 다르게 적힌 곳, 교차 참조가 다른 조를 가리키는 곳이 있었다. 이 발견이 기업용 제안서의 '문서 정합성 점검' 모듈이 됐다.

## 데이터 원칙

이 프로젝트는 **공개된 자료만** 사용한다. 약관과 상품설명서는 금융사와 공시 기관이 공개한 자료에서만 수집하고, 원문은 공개 레포에 올리지 않는다. 설문·테스트 응답 원본도 올리지 않고 집계와 익명 인용만 남긴다. 업무상 알게 된 비공개 자료나 개인정보는 쓰지 않는다. 이 프로젝트의 결과물은 금융 자문이나 상품 권유가 아니다.
