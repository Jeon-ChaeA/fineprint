# fineprint

> 금융 약관의 깨알 같은 조건을, 근거 조항과 함께 읽어 주는 AI 에이전트

## 왜 만드나

- 대출, 카드, 보험 약관은 길고 어렵다. 중도상환수수료, 금리 변동 조건, 연체 시 불이익 같은 중요한 조건은 대부분 원문 깊숙이 있다.
- AI가 대신 읽어 주면 편하지만, 금융 정보는 틀리면 안 된다. 그럴듯한 오답이 가장 위험하다.
- 그래서 fineprint의 목표는 "잘 요약하는 AI"가 아니라 **근거를 대거나, 모르면 모른다고 말하는 AI**다.

자세한 배경은 [docs/background.md](docs/background.md)에 있다.

## 무엇을 만드나

에이전트 코어는 하나, 쓰임새는 두 가지다.

| | 소비자용 | 기업용 |
|---|---|---|
| 사용자 | 대출·카드·보험에 가입하려는 사람 | 금융상품을 설명하고 판매하는 금융사 |
| 하는 일 | 가입 전에 불리한 조건, 숨은 수수료, 다른 상품과의 차이를 근거 조항과 함께 짚어 준다 | 상담원이 상품을 설명할 때 빠뜨린 의무 설명 항목을 잡아 준다 (금융소비자보호법 설명의무) |
| 결과물 | 기능 기획서(PRD), 동작하는 프로토타입, 성과 지표·실험 설계 | 도입 제안서(아키텍처, 보안, 기대 효과), PoC |

자세한 구조는 [docs/concept.md](docs/concept.md)에 있다.

## 설계 원칙

1. **근거 인용**: 모든 답에 약관 조항 번호와 원문을 붙인다. 근거 없는 문장은 내보내지 않는다.
2. **판단 불가**: 약관에 없거나 확신이 낮으면 "이 약관만으로는 판단할 수 없다"고 말한다.
3. **권유하지 않기**: "이 상품을 고르세요"가 아니라 "이 조건이 당신에게 이렇게 작용한다"로 말한다.
4. **평가 체계**: 정답이 있는 질문셋으로 인용 정확도와 판단 불가 응답률을 측정한다.
5. **사람의 개입 기록**: 어느 단계에서 사람이 판단했는지 남긴다.

자세한 내용은 [docs/design-principles.md](docs/design-principles.md)에 있다.

## 첫 사이클: 신용대출, 3주

| 주차 | 할 일 | 산출물 |
|---|---|---|
| 1주차: 문제 정의 | 금융 앱의 약관 노출 방식 관찰, 익명 사용자 설문 | 문제 정의 1페이지, 설문 결과 |
| 2주차: 코어 구축 | 공시 약관 수집, 조항 단위 분할, 근거 인용 에이전트, 소비자용 프로토타입 | 동작하는 프로토타입, 평가 질문셋 |
| 3주차: 패키징 | 소비자용 PRD, 기업용 도입 제안서, 빌드 로그 정리 | PRD, 도입 제안서, 빌드 로그 |

전체 로드맵은 [docs/roadmap.md](docs/roadmap.md)에 있다.

## 데이터 원칙

이 프로젝트는 **공개된 자료만** 사용한다. 약관과 상품설명서는 금융사와 공시 기관이 공개한 자료에서만 수집하며, 업무상 알게 된 비공개 자료나 개인정보는 사용하지 않는다. 이 프로젝트의 결과물은 금융 자문이 아니다.
