# 프로토타입 사용성 테스트 계획 (1차)

- **대상**: 소비자용 프로토타입 데모([app/](../../app/README.md)), 데모 링크 끝에 `#test`를 붙이면 과제 안내가 보인다.
- **방식**: 진행자 없이 혼자 써 보고 3분 설문([survey/usability.html](../../survey/usability.html)). 녹음·녹화·화면 기록은 하지 않는다.
- **참가자**: 지인 5명. 최근 3년 안에 신용대출·마이너스통장을 받았거나 알아본 사람을 우선한다. 금융업 종사자는 빼거나 따로 표시한다.
- **기간**: 링크를 보낸 날(2026-10-29)부터 일주일. 사흘째에 한 번만 다시 부탁한다. 5명이 차면 설문이 자동으로 마감된다.
- **결정**: 2026-10-27 전채아(지인 5명, 혼자 써 보고 설문, 데모 링크).

## 무엇을 알고 싶은가

D-008에서 정한 두 화면이 실제로 쓰이는지, 설문에서 나온 신뢰 조건(조항 원문, 모르면 모른다)이 화면에서 통하는지 본다.

| 질문 | 설문 문항 | 이렇게 나오면 |
|---|---|---|
| 1. 사람들이 요약만 보고 질문하지 않는가 (D-008 다시 볼 조건) | `used_samples`, `tried_own_question`, `summary_vs_ask` | 5명 중 3명 이상이 물어보기를 열지 않거나 "요약만으로 충분" → 물어보기의 위치·형태를 다시 정한다(요약 줄마다 "이 조건 물어보기" 등) |
| 2. 근거 원문이 신뢰에 도움이 되는가 | `opened_source`, `trust_source` | 원문을 펼친 사람이 절반 미만이거나 신뢰 점수 중앙값 3 이하 → 원문 표시 방식을 바꾼다(핵심 문장 강조, 길이 줄이기) |
| 3. 요약 문장을 이해하는가 | `summary_clear`, `confusing_line`, `understood_check` | 이해 점수 중앙값 3 이하이거나 같은 줄을 2명 이상 헷갈려함 → 그 줄의 표현을 고친다 |
| 4. "판단할 수 없음"을 어떻게 받아들이는가 | `cannot_judge_feel` | "답답했다"가 다수 → 판단할 수 없을 때 무엇을 확인하면 되는지(어디에 물어볼지)를 먼저 보여 준다 |
| 5. 실제로 쓸 것인가 | `would_use`, `one_fix` | 참고 지표. 5명이라 숫자보다 `one_fix`의 내용을 본다 |

5명은 비율을 말하기에 적다. 위 기준은 "다음에 무엇을 고칠지" 고르는 데만 쓰고, 결과 문서에는 사람 수로 적는다(예: 5명 중 3명).

## 과제 (데모 화면의 안내와 같다)

1. 은행 하나를 골라 '불리할 수 있는 조건'을 읽는다. 내가 대출을 받는다면 가장 조심할 조건을 하나 고른다.
2. 궁금한 줄이 있으면 '근거 원문'을 펼친다(필수 아님).
3. '물어보기'에서 내 상황과 가까운 예시 질문을 한두 개 눌러 본다. 따로 묻고 싶은 게 있으면 직접 써 본다(데모라 답은 안 나온다).
4. 3분 설문에 답한다.

과제 1의 "가장 조심할 조건"은 정답이 없다. 사람들이 어떤 조건에 반응하는지 본다(설문에서 당황한 조건 1위는 중도상환수수료, 2위는 금리가 오르는 조건이었다).

## 개인정보와 윤리

- 이름·연락처는 받지 않는다. 누가 어떤 답을 했는지 짝지을 수 없다.
- 직접 쓰는 질문(`own_question`)에는 금액·계좌·신용점수를 적지 말라고 안내한다. 응답에 개인정보가 들어오면 집계 전에 지운다.
- 응답 원본은 레포에 올리지 않는다. 집계와 익명 인용만 `research/usability-results.md`에 정리한다.
- 데모와 설문에 "학습·연구용, 금융 자문·상품 권유가 아님"을 밝힌다.

## 준비 (전채아)

1. **Apps Script 갱신**: `fineprint survey endpoint` 프로젝트에 [sheet-endpoint.gs](../survey/sheet-endpoint.gs) 새 내용을 붙여 넣고, `setup`을 한 번 실행한다(`usability` 시트가 생긴다). **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전 → 배포.** 이렇게 하면 웹 앱 주소가 바뀌지 않는다.
2. **설문 페이지 올리기**: Netlify `fineprint-survey` 프로젝트에 `survey/` 폴더(`index.html` + `usability.html`)를 통째로 다시 올린다(Netlify Drop). 주소: https://fineprint-survey.netlify.app/usability.html
3. **설문 확인**: 한 번 제출해 보고 `usability` 시트에 한 줄이 생기는지 확인한 뒤 지운다.
4. **데모 공유**: claude.ai의 데모 페이지에서 **공유 → 링크가 있는 누구나 보기**로 바꾼다. 참가자에게 보내는 링크는 데모 주소 끝에 `#test`를 붙인 것이다.
5. [outreach-message.md](outreach-message.md)의 문구로 5명에게 보낸다.

## 결과 정리

- 설문 시트의 `usability` 탭을 CSV로 내려받아 AI에게 주면 집계·인용 정리를 한다(원본은 레포에 올리지 않는다).
- 정리 문서: `research/usability-results.md`. 위 표의 "이렇게 나오면"에 해당한 항목은 [decision-log](../../docs/decision-log.md)에 D-009로 기록한다.

## 한계

- 혼자 써 보는 방식이라 "왜 그렇게 했는지"는 설문 자유 응답으로만 안다. 헷갈린 지점이 많이 나오면 2차는 1:1 관찰로 한다.
- 데모는 예시 질문 13개만 답한다. 자기 상황을 직접 물었을 때의 만족도는 이번에 볼 수 없다(`tried_own_question`, `own_question`으로 수요만 본다).
- 참가자가 지인이라 좋게 답할 수 있다. 점수보다 헷갈린 곳과 고칠 점을 더 무겁게 본다.
