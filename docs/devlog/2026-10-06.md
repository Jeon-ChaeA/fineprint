프로젝트의 방향을 정했다. 코드는 아직 없다. 무엇을, 왜 만들지를 정하는 데 하루를 썼다.

- GitHub 레포 생성, 초기 문서(README, 배경, 콘셉트, 설계 원칙, 로드맵, 결정 기록, 데이터 원칙) 작성
- AI 에이전트가 레포에 직접 기록을 남길 수 있도록 GitHub 연동 설정

## 생각의 흐름

1. **출발 질문**: 흔한 사이드 프로젝트처럼 되지 않으려면 어떻게 해야 할까?
   - 결론: "만들 수 있는 것"이 아니라 **실제 업무 현장의 문제 하나**에서 시작한다. 그리고 결과물만큼 과정을 남긴다.
2. **주제 선정**: 금융으로 정했다. 틀리면 안 되는 정보라 AI 신뢰 설계가 핵심 과제가 되고, 공시 자료가 공개돼 있다. ([D-001](../decision-log.md#d-001-주제는-금융))
3. **구조 설계**: 에이전트 코어는 하나, 쓰임새는 소비자용과 기업용 두 가지로 잡았다. ([D-002](../decision-log.md#d-002-하나의-코어-두-가지-쓰임새))
4. **코어 선택**: 세 후보를 비교했다. ([D-003](../decision-log.md#d-003-에이전트-코어는-약관상품설명서-해석))
   - 약관·상품설명서 해석: 양쪽 쓰임새가 모두 강하다 → 선택
   - 민원·VOC 분석: 소비자용이 약하다
   - 소비 패턴 코치: 이미 너무 많다
5. **첫 상품**: 신용대출, 신용카드, 보험을 비교해 신용대출로 정했다. ([D-004](../decision-log.md#d-004-첫-대상-상품은-신용대출))
6. **이름**: fineprint. 영어에서 "계약서의 깨알 같은 조건"을 뜻하는 관용어다. 상품을 카드, 보험으로 넓혀도 이름이 그대로 맞는다.

## 사람이 판단한 지점

- 주제, 코어, 첫 상품은 AI와 후보를 비교한 뒤 직접 골랐다.
- 데이터는 공개 자료만 쓰기로 했다.
- AI 에이전트의 레포 접근 권한은 이 레포 하나로만 제한했다.
