# 2026-11-02 ~ 03: 실시간 답변을 무료 Gemini로

- 공개 데모의 직접 쓴 질문에도 답하게 하려고, 비용이 들지 않는 Gemini API를 붙였다(D-010). 에이전트(검색·초안·점검)는 1.6 그대로 두고 답을 만드는 모델만 바꿀 수 있게 했다.
- 약관 데이터는 공개 레포에 두지 않는다는 원칙은 지켰다. 비공개 레포 `fineprint-data`를 만들고, PC와 배포 서버가 `scripts/get_data.py`로 받아 SHA-256을 확인한 뒤 푼다.
- 모델 고르기가 생각보다 오래 걸렸다. `gemini-flash-latest`는 짧은 질문 하나에 98초(긴 생각), `gemini-2.5-flash`는 신규 사용자에게 막혀 있었고, `gemini-3.8-flash`는 503(사용량 폭주), 시간 초과, 429(무료 한도)로 72문항을 돌리지 못했다. 1.2초에 답한 `gemini-3.5-flash-lite`로 평가했다.
- 1차 블라인드 채점: Claude O 71, flash-lite O 34 · X 6. 인용은 거의 맞았지만, 판단할 수 없는 질문(승인될지, 받아들여질지)을 조항만 옮기고 답해 버렸다. fineprint가 신뢰를 얻은 부분이라 그대로 쓸 수 없었다.
- 놓친 패턴을 묶어 코드 안전장치를 만들었다(`fineprint/guard.py`). 결과 예측 질문이면 "판단할 수 없음"을 앞에, 질문이 지목한 문서가 수집 문서에 없거나 조항 표기 경고가 있으면 "확인 필요"를 뒤에 붙인다. 72문항 중 일반 문항 54개에는 하나도 걸리지 않았다. 다만 이 문항들을 보고 만든 규칙이라, 처음 보는 질문으로 다시 확인해야 한다.
- 2차 블라인드 채점: flash-lite O 39 · △ 32 · X 1. 틀린 답은 거의 없어졌지만, 답이 Claude의 절반 길이라 요건 문구나 예외가 자주 빠진다. 프롬프트 끝에 덧붙인 Gemini용 지시는 거의 효과가 없었다.
- 전채아 결정: flash-lite로 베타 공개한다. 직접 쓴 질문의 답에는 베타 안내를 달고, 예시 질문은 검증된 Claude 답을 그대로 보여 준다.
- 실수: PC 폴더에 고친 파일을 같은 이름으로 다시 보냈을 때 예전 버전이 그대로 써진 일이 있었다(`--skip-list` 오류). 이후 파일을 보낼 때마다 PC 쪽 크기를 확인했다.

## 배포

- Render Blueprint로 배포했다: https://fineprint-i8hy.onrender.com . 공개 레포 주소로 만들어 Render에 GitHub 계정 권한을 주지 않았다(대신 push 때 자동 배포는 안 되고 대시보드의 Manual sync로 반영한다).
- 비공개 레포는 fineprint-data만 읽을 수 있는 Fine-grained 토큰(Contents: Read-only, 90일)으로 받는다. 키와 토큰은 Render 대시보드에만 있다.
- 배포 후 확인: 문서 10개를 읽었고, 카카오뱅크 연체이자 질문에 3.6초 만에 근거 3개를 달아 답했다.
- 토큰은 90일 뒤(2027-02-01쯤) 만료된다. 그 전에 새로 만들어 Render 환경 변수를 바꿔야 한다.

## 안전장치 확인

- 규칙을 모르는 에이전트가 쓴 새 45문항으로 정규식 안전장치를 확인했더니 판단 불가 15개 중 4개만 잡았다. 72문항에 맞춘 과적합이었다([결과](../../eval/results-guard.md)).
- 질문 종류만 묻는 AI 분류기를 더했다. v1은 새 45문항을 다 맞혔지만 72문항의 사정 이야기형 규칙 질문 7개를 잘못 잡았다. 지시를 고친 v2를 사정 이야기 위주의 새 40문항으로 다시 확인했다: 처음 보는 85문항에서 판단 불가 26/26, 없는 문서 14/14, 오탐 2/45.
- 확인하다가 '하나요'를 하나은행으로 읽는 은행 이름 버그를 찾아 고쳤다. 실제 서버에서 은행 이름 없는 "~하나요?" 질문이 엉뚱한 은행 문서를 검색하고 있었다.
- 오탐을 줄이려고, 분류기만 걸린 경우에는 "단정할 수 없는 부분이 있다"로 말을 누그러뜨린다.

## 사용성 테스트 2차 (AI 가상 사용자)

- 참가자 없이 진행하기로 해서(전채아 결정), 대출 경험이 있는 가상 인물 5명을 AI가 연기했다. 실제 사람이 아니라는 점을 결과 문서 맨 위에 적었다.
- 인물들이 쓴 질문 10개는 실제 배포 서버에 보냈다. 한 사람(IP)당 10분 5개 제한 때문에 나눠 보냈고, 중간에 브라우저 스크립트가 멈춰 한도를 한 번 더 기다렸다.
- 가장 큰 발견은 카카오뱅크 요약 줄 오류다("해약금 부과"인데 상품설명서는 신용대출 해약금 없음). 사람이 근거와 대조했던 요약인데도 놓쳤다. 두 인물이 요약과 답이 다르다며 헷갈려 했다.
- 직접 쓴 질문 10개 중 틀린 답 2개(금리인하요구권 요건 없다고 함, 신용대출에 주택담보 조건), 근거 없는 답 1개가 실제 서버에서 나왔다.
- '물어보기 →'는 5명 중 아무도 누르지 않았다. 흐리게 바꾼 결정을 다시 봐야 한다.
- 2차 결과 1~6을 모두 반영했다. 요약 18줄 재대조에서 고칠 줄 3개가 나왔지만, 하나(카카오 연체이자)는 차이가 사소하고 근거 조각이 없어 고치지 않았다. 새 안전장치(주택담보 혼동)는 처음에 "1개월(주택담보대출은 2개월)"처럼 바르게 구분한 예시 답 2개에도 걸려 조건을 좁혔다.
