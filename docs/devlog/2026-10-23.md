# 2026-10-23: 에이전트 1.6, 소비자용 프로토타입

## 에이전트 1.6

- 1.5에서 내려간 3문항을 고쳤다([결과](../../eval/results-v1.6.md)).
  - K09(검색): 질문의 "다시 평가", "자동으로 평가"를 설명서의 "재평가·재산출", "자동화평가"로 잇는 용어 두 줄.
  - Q11·Q13(답 쓰기): 점검 단계에 "짝" 항목. 비교 질문이면 둘이 만나는 지점을, 사유를 물으면 나란히 적힌 사유를 함께 쓴다.
- 근거 목록이 바뀐 문항이 K09 하나라, 나머지는 1.5 초안을 그대로 두고 점검 단계만 다시 돌렸다.
- 72문항 O 68 → 70. 대상 3문항은 3번 모두 O. 대신 K04가 내려갔고(근거에 있는 해지권을 지우거나 옆 사실을 잘못 붙임), 답이 15% 길어졌다.

## 소비자용 프로토타입

- D-008의 두 화면을 만들었다: 불리할 수 있는 조건 요약, 조항 근거 답변([app/](../../app/README.md)).
- 요약은 답변과 같은 원칙으로 만든다. 주제별로 검색한 근거 안에서만 LLM이 쓰고, 근거 번호는 코드가 조각으로 되돌린다.
- 요약 18줄을 근거와 대조하다 LLM이 같은 쪽의 다른 창(500자 조각)을 댄 줄을 찾았다(토스뱅크 신용점수 줄). 구절마다 가장 잘 맞는 조각을 코드가 더하고, 같은 쪽의 더 맞는 창이 있으면 원래 근거를 빼게 했다. 줄의 숫자가 근거 원문에 없으면 표시한다(이번 18줄은 모두 원문에 있었다).
- 레포에는 원문을 넣지 않는다. 화면은 로컬 `data/processed`에서 원문을 읽고, 요약·예시 답 파일에는 조각 id만 둔다.
- API 키가 없을 때는 데모 모드로 요약과 예시 질문 13개만 보여 준다.
