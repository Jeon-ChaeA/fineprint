# 2026-10-10: 에이전트 1.1과 재평가

## 오늘 한 일

- 1차 평가의 AI 초벌 채점(O 24 · △ 7 · X 1)을 전채아가 확인했다. 고친 등급은 없었고, 이 숫자를 1.1의 기준선으로 삼았다.
- 기존 32문항에만 맞춰 고치지 않도록 **새 문항 10개**를 먼저 만들었다. 에이전트를 고치기 전에, 고치는 쪽과 다른 AI가 만들고 또 다른 AI가 원문과 대조했다. 1.0으로도 먼저 돌려 기준선을 남겼다(O 5 · △ 4 · X 1).
- 에이전트 1.1을 만들었다.
  - 층별 검색: 기본약관·약정서·설명서에서 각각 상위 4개 단위
  - 설명서 한 쪽이 여러 조각이어도 한 단위로 세기
  - 3,000자 이하 문서는 통째로
  - 약정서·설명서가 가리키는 기본약관 조를 바로 뒤에 넣기
  - 수집한 문서 목록을 함께 주고, "결과까지 쓰기"와 "없는 문서는 확인 필요" 규칙 추가
- LLM 없이 근거 재현율부터 쟀다. 기존 문항 82% → 94%, 새 문항 68% → 91%.
- 재평가: 답 정확도 기존 75% → 88%, 새 문항 50% → 70%. 함정 탐지 3/3, 1/1. 권유·지어낸 인용 0건. ([결과](../../eval/results-v1.1.md))
- 자동 채점에서 "더 낫다고 말씀드릴 수는 없고"를 권유로 잡는 오탐이 있어 부정문을 빼도록 고쳤다. 검사기가 ①②를 숫자 항으로 세던 것도 고쳤다(44건 → 16건).

## 배운 것

- 1.0의 감점은 절반이 검색 탓이었는데, 1.1에서는 거의 다 **답 쓰기** 탓이다. 근거 목록에 서면 독촉 후 10일, 인지세 7만원이 있는데도 답에서 빠졌다.
- 근거를 늘리자 부작용이 하나 생겼다. 1.0에서 맞던 Q16이 이름이 비슷한 다른 제도(채무조정요청권)를 섞어 △가 됐다. 근거가 많아지면 구분하는 일이 생긴다.
- 근거 목록이 2.4배 길어졌다. 지금 규모에서는 괜찮지만 상품이 늘면 상한을 다시 정한다.
- 새 문항에서도 같은 방향으로 좋아졌다. 기존 문항에만 맞춘 개선이 아니라고 볼 근거다.

## 사람이 판단한 지점

- 전채아: 1차 평가 채점 확인, 1.1 진행 결정
- AI: 1.1의 구체적인 설계(층별 개수, 짧은 문서 기준 3,000자, 근거 상한 26조각)와 새 문항 작성. 숫자는 근거 재현율을 보고 정했고, 새 문항으로는 튜닝하지 않았다
- 이 작업 환경에 API 키가 없어 답 생성은 1차와 같은 방식(같은 프롬프트를 Claude Sonnet에)으로 했다
