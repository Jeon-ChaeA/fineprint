# 2026-10-20: 작업 방식 정리 (토큰·시간 줄이기)

## 왜

- 1.4 평가 결과를 레포에 올리는 데 하위 에이전트 두 개가 약 95만 토큰과 30분 넘게 쓰다 사용량 한도에 걸렸다.
- 원인: 이 작업 환경에서는 `git push`를 못 해서, GitHub 연결 도구에 파일 내용을 AI가 글자 그대로 다시 써서 넘겼다. 약 1MB의 답 원문·채점지를 옮겨 쓰고 대조하느라 비용이 컸다.

## 바꾼 것

1. **푸시는 전채아 PC에서 git으로 한다.** AI는 바뀐 파일을 PC의 폴더에 넣고, 전채아가 `git add/commit/push`를 한다.
2. **실행 원자료는 레포에 올리지 않는다.** 답 원문(`answers_r*.jsonl`), 3회 채점지(`grading_3x.md`), 블라인드 원본(`blind_*.json`)은 로컬 `runs/`에만 둔다(.gitignore). 레포에는 결과 문서와 `score*.md`만 올린다. 이번 정리 전에 일부 올라간 원자료는 추적에서 뺐다(`runs/v1.3-rerun`은 1.3 결과 문서가 참조해 그대로 둔다).
3. **답 생성은 API 키가 있으면 스크립트로 돌린다**(`run_eval.py generate`). 하위 에이전트가 300KB짜리 프롬프트 파일을 통째로 읽는 방식은 API 키가 없을 때만 쓴다.
4. **문항당 3회 평가는 버전을 최종 비교할 때만 한다.** 개발 중에는 처음 보는 문항셋 하나를 1회 돌린다.

## 사람이 판단한 지점

- 전채아: 위 네 가지로 작업 방식을 바꾸고, 푸시는 PC에서 하기로 결정

## 그 밖에

- 전채아가 1.4 채점지를 확인했다. 바꾼 등급 없이 확정(기존 32문항 O 30, H O 6, J O 10, K O 9).
- 바뀐 작업 방식으로 첫 푸시를 했다(전채아 PC의 `fineprint-repo`에서 `git push`, 31개 파일, 11.6KB).

## 에이전트 1.5: 검색 보강

- 1.4 감점 7문항 중 4~5문항은 근거 목록에 재료가 없었다. 답 쓰기는 그대로 두고 검색만 고쳤다([결과](../../eval/results-v1.5.md)).
- 근거 재현율을 **항 단위**로도 세기 시작했다. 조 단위로만 세면 제7조 ①만 들어가도 ③을 맞힌 것으로 쳐서, 1.4의 재현율(조 단위 약 94%)이 실제보다 좋아 보였다. 항 단위로는 86%였다.
- 바꾼 것: 같은 내용 조각 빼기(하나은행 설명서 중복 쪽), 설명서 한 쪽 2조각까지 + 설명서 5쪽까지, 항까지 참조 따라가기(통째로 넣은 추가약정서 포함), "안 하면" 류 질문에 결과 조항(제7조 ③·④) 잇기, 콕 집어 넣은 조각은 상한에서 자르지 않기(상한 30).
- 근거 재현율(항 단위) 86% → 97%. 근거 목록 글자 수는 그대로(약 12,200자).
- 새 문항 4차(L)를 1.5를 고치기 전에 만들고, 1.4와 1.5를 1회씩 블라인드 비교했다. O 7 → 8, X 1 → 0. 내려간 L08은 근거가 같은데 결론을 유보한 답 쓰기 흔들림이다.
- 비용: 이번부터 재현율을 먼저 재고 LLM 평가는 새 문항 10개 × 2버전 × 1회만 했다(1.4 평가의 약 1/6).
